---
title: Authentication
description: Authenticate the rafflesia CLI with OAuth, an access token, or an API key.
---

## Browser OAuth

OAuth with PKCE is the default login:

```bash
rafflesia auth login
```

The CLI starts a loopback callback listener, opens the AuthKit authorization
URL, validates the callback state, exchanges the code, and stores the access
and refresh tokens through the generated public SDK's credential-free `Auth`
service. It refreshes the access token when it is within one minute of expiry.
For a headless shell:

```bash
rafflesia auth login --no-open
```

Optional `--provider`, `--connection-id`, `--organization-id`, `--login-hint`,
and `--domain-hint` flags narrow the authorization request. Force a refresh at
any time with:

```bash
rafflesia auth refresh
```

## Access tokens

Store an existing OAuth access token:

```bash
rafflesia auth login --access-token "$RAFFLESIA_ACCESS_TOKEN"
```

This path does not have a refresh token; replace it when it expires.

## API keys

Store an API key:

```bash
rafflesia auth login --api-key "$RAFFLESIA_API_KEY"
```

Access tokens and API keys are both sent as bearer credentials. Resolution order
for API commands is:

1. `--access-token` or `--api-key`, plus `--server`
2. `RAFFLESIA_ACCESS_TOKEN`, then `RAFFLESIA_API_KEY`, plus `RAFFLESIA_API_BASE_URL`
3. the stored login
4. `https://api.rafflesia.ai` for the server

The two credential flags are mutually exclusive.

## Storage and logout

Inspect the effective method without printing the full credential:

```bash
rafflesia auth status
rafflesia auth verify
```

`auth verify` sends an authenticated capabilities request. An invalid or
expired bearer credential fails with the API's structured authentication error.

The CLI writes `rafflesia/config.json` below the operating system's user config
directory atomically with mode `0600`. Set `RAFFLESIA_CONFIG_PATH` to use an
exact isolated path. Remove the stored login with:

```bash
rafflesia auth logout
```

<Warning>
  Prefer credential environment variables over command-line flags in shared
  environments because flags can appear in shell history and process listings.
</Warning>
